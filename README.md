# 🏥 Smart Elastic Appointment Scheduling Engine

מערכת Backend מתקדמת ב-**Spring Boot** לניהול חכם של יומני רופאים, אופטימיזציית זמני הגעה (ETA) בזמן אמת, ומזעור "זמן מת" במרפאות תחת אילוצי מקביליות קשיחים.

---

## 🎯 הבעיה ההנדסית והעסקית
מערכות זימון תורים מסורתיות מתייחסות ליומן הרופא כאל רשימה סטטית. בעולם האמיתי, איחור של מטופל אחד מייצר שני כשלים:
1. **זמן מת לרופא (Doctor Idle Time):** הרופא ממתין בחוסר מעש עד להגעת המטופל המאחר.
2. **אפקט דומינו (Cascading Delays):** דחיית כל התורים הבאים ופגיעה ישירה במטופלים דייקנים שהגיעו בזמן.

מערכת זו פותרת את הבעיה באמצעות **מנוע תזמון אלסטי בזמן אמת (`RealTimeEtaOptimizer`)** המחשב מחדש את חלון הזמן הפעיל ברגע קבלת דיווח על איחור או הקדמה, תוך אכיפת שני אילוצי ברזל עסקיים:
* **מגן הדייקנים:** מטופל שהגיע בזמן (או הקדים) לעולם לא יידחה מעבר לשעת התור המקורית שלו (`actualStart <= originalStart`).
* **אילוץ זמינות פיזית:** המערכת לעולם לא תקדים תור למטופל שטרם הגיע למרפאה (`actualStart >= max(cursorTime, reportedEta)`).

## 🧠 ארכיטקטורה, אלגוריתמיקה והחלטות תכנון (System Design)

### 1. אלגוריתם תזמון אלסטי (`Branch-and-Bound` עם פונקציית עלות אסימטרית)
במקום אלגוריתם חמדן (Greedy) שעלול לשבץ מטופל בחור קצר מדי ולדרוס מטופלים דייקנים בהמשך היום, המערכת מריצה חיפוש מרחב מצבים (Backtracking עם Early Pruning) על חלון הזמן הפעיל:
* **מילוי חורים חכם (Gap Filling / Swapping):** אם לדני יש תור של 30 דקות ב-`10:00` והוא מאחר ל-`10:10`, וליוסי יש תור של 10 דקות ב-`10:30` אך הוא דיווח שהגיע מוקדם ב-`09:59` – פונקציית העלות קונסת בכבדות על זמן בטלה של רופא (`120.0` נקודות לדקה) ונותנת בונוס על קידום מטופל זמין (`-5.0`). כתוצאה מכך, המערכת מחליפה ביניהם אוטומטית: יוסי נכנס ב-`10:00–10:10`, ודני נכנס מיד אחריו ב-`10:10–10:40`. **0 דקות של זמן מת לרופא**.
* **תעדוף מאחרים מדורג:** פונקציית קנס היפרבולית מוודאת שבמקרה של מספר מאחרים ברצף, מטופל שאיחר בדקות בודדות יישמר קרוב יותר לשעתו המקורית לעומת מטופל שאיחר באופן קיצוני. מאחר שאינו יכול להשתבץ מבלי לפגוע בדייקנים מועבר אוטומטית לרשימת המתנה מתועדפת (`PriorityQueue`).

### 2. עוגני זמן למניעת סחף יומן (Stateful Temporal Anchors)
כדי לתמוך בקריאות HTTP בלתי תלויות לאורך היום (למשל, דיווח הקדמה ולאחריו דיווח איחור בקריאה נפרדת), הישות `Appointment` שומרת מאחורי הקלעים (`@JsonIgnore`) את עוגני המקור (`originalStartTime`, `originalEndTime`, `reportedEta`). כך האלגוריתם תמיד מודע לגבולות החלון המקוריים ואינו מאבד מידע בין עדכונים.

### 3. הגנה דו-שכבתית ומניעת Race Conditions במילי-שנייה (TOCTOU Protection)
כאשר שני מטופלים מנסים לקבוע תור לאותו רופא ולאותה שעה בדיוק באותה מילי-שנייה, בדיקה בזיכרון בלבד עלולה להיכשל (Time-Of-Check to Time-Of-Use), שכן שני התהליכונים יראו שהמשבצת פנויה לפני שהשני הספיק לשמור. המערכת מיישמת הגנה כפולה:
1. **שכבה ראשונה בזיכרון (`IntervalTree`):** עץ קטעים הבודק חפיפות טווחי זמן שרירותיים (כגון `10:00–10:30` מול `10:15–10:45`) בסיבוכיות זמן של $O(\log N)$.
2. **שכבה שנייה במסד הנתונים (`@UniqueConstraint`):** אינדקס ייחודי אטומי ברמת ה-DB על העמודות `(doctorId, startTime)`. אם שני תהליכונים עברו את בדיקת ה-`IntervalTree` באותה מילי-שנייה בדיוק, מנוע מסד הנתונים יבלום אטומית את הכתיבה השנייה ויזרוק `DataIntegrityViolationException`, שמתורגם ב-Controller לתגובת `409 Conflict` נקייה.

### 4. בקרת מקביליות ברמת הרופא (Lock Striping)
במקום נעילה גלובלית (`synchronized`) שתיצור צוואר בקבוק כלל-מערכתי, השירות מממש **Lock Striping** באמצעות `ConcurrentHashMap<Long, ReentrantLock>` עם מנעולים הוגנים (`fair = true`). כל רופא מנוהל תחת מנעול עצמאי, מה שמאפשר עיבוד מקבילי מלא (High Concurrency) בין רופאים שונים ובטיחות תהליכונים מוחלטת בתוך יומן של רופא בודד.

### 5. סנכרון מנוע ה-Write-Behind של Hibernate (`Two-Phase Update` & `flush()`)
בתוך טרנזקציה (`@Transactional`), Hibernate מבצע פעולות SQL בסדר קבוע (`INSERT` -> `UPDATE` -> `DELETE`). כדי למנוע התנגשות עם ה-`UniqueConstraint` בעת החלפת תורים או בעת מחיקת תור ושיבוץ מיידי מרשימת ההמתנה לאותה משבצת, המערכת מבצעת הזזה דו-שלבית דרך אזור חיץ זמני (Buffer Zone) ואוכפת סדר ביצוע פיזי מול ה-DB באמצעות קריאות `flush()` מפורשות.

## 🚀 נקודות קצה (REST API Endpoints)

| Method | Endpoint | תיאור הפעולה |
| :--- | :--- | :--- |
| `POST` | `/api/appointments` | יצירת תור חדש (ולידציית חפיפות ב-`IntervalTree` ואינדקס ייחודי ב-DB) |
| `GET` | `/api/appointments` | שליפת כלל התורים הפעילים במערכת |
| `POST` | `/api/appointments/{id}/eta` | דיווח ETA (איחור/הקדמה בפורמט `yyyy-MM-dd'T'HH:mm`) והרצת אופטימיזציית הלו"ז |
| `POST` | `/api/appointments/waitlist` | הוספת מטופל לרשימת המתנה מתועדפת (`PriorityQueue`) לפי רמת דחיפות |
| `DELETE` | `/api/appointments/{id}` | ביטול תור ושיבוץ אוטומטי מיידי של המטופל הדחוף ביותר מרשימת ההמתנה |
